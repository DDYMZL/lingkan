# 玲看股息 LingKan 项目宪法（constitution.md）

> 版本：v1.1　生效日期：2026-10-30
> 约束对象：本项目全部参与者（含 AI 编程工具）。任何与本文件冲突的代码、配置、文档均以本文件为准。

## 一、项目定位

1. 本项目是**个人使用的 A 股数据查询与分析微信小程序**，名称为「玲看股息 LingKan」。
2. 产品形态**只能是微信小程序**。不开发 PC 管理后台，不开发独立 Web 管理系统。
3. 项目根目录固定为 `D:\project\lingkan`，一级目录固定为 `frontend`、`backend`、`docker`、`docs`。
4. 技术栈固定：前端微信小程序原生（WXML + WXSS + JavaScript + JSON，不使用 uni-app / Taro 等跨端框架）；后端 Java 25 + Spring Boot 4.1.x + MyBatis-Plus + openGauss；部署使用 Docker Compose。

## 二、十三条铁律

### 1. 文档优先
任何功能开发前必须先有 Spec（需求 / 设计 / 任务 / 验收）。未经确认的 Spec 不得进入编码。

### 2. 指标配置化
指标清单、显示名称、精度、单位、排序、展示位置全部可配置。**禁止把指标字段写死在前端页面或后端业务代码里**。

### 3. 数据源解耦
每个指标可绑定多个数据源，数据源之间通过统一接口隔离。**禁止在 Controller 中直接调用第三方接口**，必须经过 `StockDataProvider` 适配器。

### 4. 数据来源可追溯
任何一个展示出来的数值，都必须能回答：来自哪个数据源、数据所属时间是什么、实际采集时间是什么。

### 5. 历史数据可追溯
只允许新增历史记录与新增迁移脚本，**禁止随意删除或修改历史数据与历史迁移脚本**。

### 6. 不允许虚构数据
- 拿不到数据时返回 `MISSING` / `--`，**禁止用 0、估值、模拟值填充**。
- 禁止编造数据源接口、字段含义或调用限制。
- 数据源是否免费、是否可用、频率限制，必须以**真实请求结果**为准，不得引用未验证的第三方文章。

### 7. 前端必须是微信小程序
页面按移动端交互设计，遵守小程序页面栈、下拉刷新、上拉加载等规范。**禁止使用浏览器专属 API**。图表必须使用经验证的小程序兼容方案（canvas 2d + echarts）。

### 8. 不开发 PC 管理后台
所有配置能力通过小程序内的「我的 / 指标配置 / 数据源配置」页面完成。

### 9. 业务逻辑不得全部写在页面中
页面只负责展示与交互；数据获取、格式化、状态判断放在 service / composable / store 层。

### 10. 所有指标公式必须有明确说明
每个指标必须登记 `calculation_expression` 与 `calculation_status`。
**公式未确认（PENDING）的指标不得实现计算，也不得对外输出数值。**

### 11. 关键计算必须有单元测试
至少覆盖：负 PE、零利润、负利润、股息率为零、多次现金分红、未实施分红、财报未披露、60 日新低、周线数据不足、数据源超时、多源结果不一致。

### 12. 修改功能必须同步修改文档
代码变更必须同时更新对应 Spec 与 `docs/changes/changelog.md`。

### 13. 功能完成即提交
**每完成一个功能，必须立即 `commit` 并 `push` 到 GitHub 远程仓库 `origin/main`（`https://github.com/DDYMZL/lingkan.git`）。**

- 「完成」的判定：可编译/可运行 + 测试通过 + 文档与 changelog 已同步。
- 一次功能 = 一次 commit + 一次 push，禁止多个功能攒批提交，禁止只提交不推送。
- 提交信息遵循 `type(scope): 中文描述`，细则见 `docs/GIT_WORKFLOW.md`。
- 鉴权或网络导致 push 失败时，必须显式告知用户「本地已提交、远程未推送」，并在下一次动作前补推。
- 禁止入库：`.tools/`、`.backup/`、`backend/target/`、`node_modules/`、`.env`、密钥文件、日志。

## 三、AI 编程工具执行纪律

1. 每次开始工作前先读取本文件。
2. 先阅读相关 `docs/specs/*`，再动代码。
3. 一次只处理一个明确功能，不擅自改动其他模块。
4. 不擅自改变已确认的指标公式；不删除历史数据；不编造接口。
5. 完成后必须：运行测试 → 更新文档 → 更新 changelog → **commit 并 push 到 GitHub（铁律 13）**。
6. 遇到信息缺失（如公式口径、接口限制），**先提问并记录到 Spec 的待确认项**，不得自行假设后直接实现。

## 四、版本与依赖纪律

1. 优先采用当前最新稳定版，不使用 SNAPSHOT / RC / M 版本。
2. 所有依赖必须核实兼容性；若最新版与生态不兼容，采用经验证的稳定组合并在 `docs/decisions/ADR` 记录理由。
3. 版本号最终记录在 `docs/architecture/backend-architecture.md` 的技术选型章节。

## 五、数据安全

1. 数据源 Token / 密钥只保存在服务端环境变量，**接口不得返回明文**。
2. 小程序端不直连任何第三方行情接口。
3. 不做多用户注册登录体系，但所有用户级配置保留 `user_id` 维度。

## 六、版本控制

1. 本项目与远程仓库 `https://github.com/DDYMZL/lingkan.git` 关联，远程别名 `origin`，主分支 `main`。
2. 每完成一个功能必须提交并推送（铁律 13），完整执行细则见 **`docs/GIT_WORKFLOW.md`**，该文件与本宪法同等效力。
3. 提交前必须通过 `.gitignore` 与自检清单确认未纳入工具链、构建产物与密钥。
4. 已推送的历史不重写；回退使用 `git revert`，禁止对 `main` 强推。
