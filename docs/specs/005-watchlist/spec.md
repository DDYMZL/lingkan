# 005-自选股 · 需求规格

> Spec 状态：`approved`
> 版本：v1.1（新增首页看板接口引用，由 spec 010 修订）
> 日期：2026-10-31

## 一、需求

用户可在小程序内维护一份自选股列表，支持添加、删除、排序、备注，并**按用户指标配置动态展示指标值**。

第一版为单用户，`user_id` 固定为 `local-user`，但表结构保留 `user_id` 维度以便未来扩展。

## 二、功能需求

| 编号 | 需求 |
|---|---|
| FR-5.1 | 从市场列表、搜索结果、股票详情页均可「加自选」 |
| FR-5.2 | 自选列表按用户自定义 `sort_order` 展示，支持拖动排序并持久化 |
| FR-5.3 | 支持删除自选（`DELETE /watchlist/{stockCode}`） |
| FR-5.4 | 支持为每只自选股添加备注 |
| FR-5.5 | 自选列表的指标列完全由 `user_metric_preferences.show_in_watchlist` 决定 |
| FR-5.6 | 支持自选股批量刷新行情（异步） |
| FR-5.7 | 重复添加同一股票必须幂等，不产生重复记录 |
| FR-5.8 | 首页看板使用 `GET /api/v1/watchlist/board` 全量快照，行顺序沿用自选 `sort_order`；看板固定字段与九档目标价由 spec 010 定义，不改变本 Spec 动态指标列表接口 |

## 三、业务规则

- 唯一约束：`(user_id, stock_id)`。
- 排序值连续递增，重排时整表重写 `sort_order`。
- 删除为物理删除（自选是用户偏好数据，不属于"历史数据"，不受宪法原则六约束）。
- 自选股数量第一版不设上限；原 `/watchlist` 列表前端分页加载，首页 `/watchlist/board` 为看板全量快照。
- 添加自选成功后由后端异步触发分红/财务即时同步；返回首页时重新拉取看板，无需前端重复调用同步接口。

## 四、非功能需求

| 项 | 要求 |
|---|---|
| 性能 | 50 只自选股列表接口 P95 < 1.5s（依赖行情缓存） |
| 一致性 | 添加/删除后立即生效，不做乐观缓存 |
| 降级 | 某数据源失败时，该指标显示「数据不可用」，不阻塞整个列表 |
