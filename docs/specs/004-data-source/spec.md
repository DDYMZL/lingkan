# 004-数据源中心 · 需求规格

> Spec 状态：`approved`（用户已提供技术文档，视为需求已明确）
> 版本：v1.0
> 日期：2026-10-30

## 一、需求背景

系统必须支持多个行情/财务数据源，且用户可以在小程序内自行启用、停用、切换数据源，并对比同一指标在不同数据源下的取值。

**不得**把数据源写死在业务代码中，**不得**在 Controller 中直接调用第三方接口。

## 二、功能需求

### FR-4.1 数据源注册与展示

系统内置一批数据源，在小程序「我的 → 数据源配置」中以卡片形式展示。每个数据源需展示：

- 数据源名称、类型
- 支持的能力（行情 / 历史K线 / 财报 / 分红 / 股票列表）
- 启用状态
- 是否需要 Token
- 请求间隔限制
- 最近成功时间、最近失败时间
- 最近错误信息
- 健康状态

### FR-4.2 启停控制

用户可对每个数据源执行启用 / 停用。停用后该数据源不参与任何取数，也不出现在指标可选数据源中。

### FR-4.3 连接测试

用户可对单个数据源发起「测试连接」，后端发起一次真实请求并返回：是否成功、耗时、返回样本摘要、错误信息。

**测试必须是真实请求**，不允许返回硬编码的"连接正常"。

### FR-4.4 优先级与绑定

每个指标可绑定多个数据源，绑定关系含：优先级、是否主源、超时、缓存秒数。取数时按优先级顺序尝试。

### FR-4.5 多源对比

对任意 股票 × 指标，可查询所有已绑定数据源的返回值，返回结构必须包含每个来源的：
`来源代码、数值、单位、数据所属时间（dataTime）、实际采集时间（fetchTime）、状态、与主源差异`。

**禁止**对多源数值求平均。

### FR-4.6 降级策略

主源失败时可按优先级降级到备用源，但返回结果必须明确标注真实来源，**不得冒充主源数据**。

### FR-4.7 调用日志

每次采集需记录：数据源、指标、同步类型、开始/结束时间、总数、成功数、失败数、状态、错误信息。

### FR-4.8 Token 安全

需要 Token 的数据源，Token 只存服务端。任何对小程序返回的接口响应中**不得出现 Token 明文**。

## 三、非功能需求

| 项 | 要求 |
|---|---|
| 限流 | 每个数据源有最小请求间隔（默认 500ms），后端必须实际遵守 |
| 超时 | 单次请求默认 5s，可配置 |
| 缓存 | 行情类指标默认缓存 60s，估值类 300s |
| 可追溯 | 每次取数保存 `raw_payload`，便于字段口径回溯 |
| 失败可见 | 接口失败必须返回明确状态（`TIMEOUT` / `ERROR` / `MISSING`），不得静默返回空值冒充成功 |
